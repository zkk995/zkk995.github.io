Dream-RSI 论文解读：让 Agent 在"梦"里学会更会探索

论文：Dream-RSI: Recursive Self-Improvement through Evolving Worlds（2026-09 提交，Tong Zheng 等，Google 系团队）｜四域 9 个发现任务：GPU kernel、数学优化、算法工程、Harness 优化
不改模型权重，让"探索策略"自己越变越强。
一句话核心：Agent 探索走过的每一步都存在一棵"发现树"里，这棵树就是现成的回放模拟器——改进探索策略时不必再花钱重跑真实探索，而是在历史树里"做梦"试走千百条别的路线，几乎零成本选出更好的策略再上线继续发现，形成不改模型权重的递归自我改进（RSI）闭环。

1. 背景：探索策略是个"没人付得起学费"的角色

LLM 驱动的科学发现（AlphaEvolve、OpenEvolve 这类进化搜索）里，真正决定成败的往往不是模型本身，而是探索策略：往哪个方向分叉、开多少并发、什么候选值得精修、什么时候收手。问题是这个角色的反馈又贵又慢——一次探索要跑几十上百次 agent 调用，好坏要等整个长程 rollout 结束才知道。想改进它，就得反复做昂贵的在线评估，等于让"教练"陪跑每一场比赛才能学会执教。

另一条思路是把历史轨迹压缩成几条"经验教训"塞进提示词当语义引导。论文后面用实验打了脸：这种显式引导反而拖累两个方法的表现（ConvDiv 任务上，无论固定策略还是 Dream-RSI，加了引导都变差），因为几句话的抽象会约束探索的多样性。

Dream-RSI 的出发点是一个很优雅的转念：已走过的路本身就是一个模拟器。就像model-based RL（Dreamer 系列）学一个世界模型来"在梦里开车"，发现历史记录了"在每个决策点、每个动作得到了什么结果"——换一个策略只是换一条走树的方式，结果早就在树上存着，揭示即可，无需重跑。

2. 方法：三层循环——在线探索 → 造梦 → 换策略上线

整个系统只有一个可变部件：探索策略的代码（policy code）。模型、评测器、执行接口全部冻结。流程是：

① 在线探索当前策略指挥固定的发现 agent 走出真实 rollout，产出带完整轨迹和评分的发现树，存入历史池。
② 造回放模拟器把所有历史发现树变成"回放世界池"：每个节点存着工作区快照、观测与得分，父—子路径是已定结局。
③ 做梦改进策略改进 agent 审阅回放轨迹与分数，改写策略代码成新版本；每个版本在所有历史树上重放打分。
④ 择优上线取平均回放分最高的版本投入下一轮真实探索；新产出又扩充模拟器池，循环往复。

发现树与统一决策接口

树根是初始工作区，每个节点是一次尝试：继承父节点的工作区快照，产出候选并由固定评测器打分。策略的动作是一批节点选择（批量 ≤ 并发数 W），决定"往哪续、开多少路"。在线阶段执行动作产生真实新结果；离线回放执行同一动作，只是确定性地揭示已记录的子节点。两个阶段共用这套决策接口，唯一区别是状态转移方式——这正是"同一个策略，两个世界"的设计。

回放打分：质量—成本的帕累托，外加"爱并行"的偏置

Vim = (1/Bi) Σj (āi,jm − āi,j−1m)(Bi − n̄i,jm) − λ·(1/|ℛ|) Σρ k⋆i,ρm/ni,ρm

第一项：策略在不同预算偏好 ρ∈{0,0.25,0.5,0.75,1} 下扫出的质量—成本帕累托前沿的归一化超体积——用更少的 agent 调用拿到更高分就奖励。第二项：并行度惩罚——完成更多轮次才换来同样调用量（串行磨洋工）要扣分。

每次离线改进会生成 M 个候选策略版本，全部在全部历史树上回放，取平均分最高者上线。由于当前版本也在候选之列，改进永不劣化。

"做梦"与在线的关系

回放只能评估"已见过的世界"里的策略，off-policy 选出的好策略不保证在线同样好。Dream-RSI 的答案是：把改进后的策略放回真实环境继续滚，新树进池、下一轮再梦——在线探索为模拟器"补充弹药"，模拟器为在线探索"挑选大脑"，两边互相喂养。累积全部历史 vs 只用当轮历史的消融（ConvDiv 1.90 vs 1.59）证明池子越大，学出的策略越通用、不易过拟合单个世界。

用户材料核对

  • "317 次调用达到 51,200 代的效果"——属实且偏保守：317 次调用（Gemini-3.1-Pro）不仅追上，还在六个留存数据集上把平均运行时从 3587.1 ms 压到 2931.0 ms；论文自述约为 SimpleTES 计算量的 1/162（Flash 骨干为 1/27）。
  • "圆填充追平 AlphaEvolve V2"——属实：2.635983，与 AlphaEvolve V2 / ShinkaEvolve / TTS-Discovery 并列最强。
  • "GPU kernel 优化生成次数减少 2.43×"——属实：VGG16 上同性能少 2.43× 代数（LayerNorm 为 1.79×）。

三个值得记住的次要发现

  • 历史即模拟器 > 历史即教训：把历史抽象成"方向性建议"塞提示词，两个方法都变差；回放式利用历史才涨分。
  • 策略学会了"张弛有度"：ConvDiv 上，改进中的策略先收着打（尝试数 110→50）省算力，遇到平台期再加大力度（50→92）换新涨分——这是学出来的，不是写死的。
  • 赢家写法有讲究：发现的 ConvDiv kernel 不逐点优化卷积，而是围绕下游池化重构算子链（max-pool 紧贴卷积输出、缩放求和推迟到最后一次归约）；发现的 Lasso 求解器把 active-set 优化做成自适应的。改进探索策略后，agent 能找到这类"换思路"级别的解。

4. 局限与实用启示

  • 梦只能梦见走过的路：回放世界是"已实现搜索空间"的模型，策略再好也无法揭示从未分叉过的方向；真正的探索空间扩张仍靠在线 rollout，闭环缺了在线侧就退化为纯离线选优。
  • 树结构是硬前提：方法要求任务能被组织成分叉的发现树、每个尝试有确定分数与可恢复的工作区快照；无评分器或环境不可复现的任务（比如纯对话）不适配。
  • 评测器冻结是双刃剑：评分协议若本身有偏，回放分高只说明"更会讨好这个评测器"；好在这套框架里换评测器只需重放，不用重训。
  • 实用启示：凡是在跑长程进化搜索/自动发现的团队，都可以把"探索策略代码"从"写死"升级为"每轮用历史树重放选优"——模型不动，改动只在编排层；预算敏感的场景受益最明显（论文中最强的一个数字就是 162× 的调用差）。
