投机解码草稿模型训练组件化框架训练系统

LEGOSpec：把草稿模型拆成乐高，控制变量找出「哪个部件在起作用」

LEGOSpec: A Composable and Efficient Framework for Speculative Draft Design and Training
Hanzhen Wang, Jiaming Xu, Guohao Dai · 上海交大 / 无问芯穹 / SII · arXiv:2611.33004 v1 2026-11-24 · 代码与权重 SJTU-DAI-Sys/LEGOSpec

一句话：草稿模型论文都在报「完整配方」，训练配置各不相同，根本分不清收益来自架构还是训练。LEGOSpec 把草稿拆成 Context / Backbone / Proposal / Objective 四块积木，在统一训练设施下做控制变量实验，得出三条结论，并据此拼出通用草稿 DFlux——常规基准接受长度超最强基线最高 13.7%、长上下文最高 34.7%，训练吞吐比 SpecForge 高 79%、离线监督准备快 3.11 倍。

1. 动机：训练配置的噪音，盖住了架构的信号

投机解码的草稿模型这一年爆发式迭代：EAGLE-3、DFlash、DFlare、DSpark、DLite、DFlash2……但每篇论文都只报「完整配方 + 自己的训练配置」。LEGOSpec 用一个实验戳破了这层窗户纸（原文图 1）：在 DFlash 上，换个优化器、或把训练集从 80K 扩到 400K，带来的接受长度变化就能追平甚至超过加一个 Markov 头的架构改动；而换数据源反而会掉点。

换句话说，文献里「方法 A 比方法 B 好」的结论里，可能混着大量训练配置的差异。要做严肃的组件研究，得有统一的基础设施——这就是 LEGOSpec 的定位。

2. 框架：四块积木 + 统一训练设施

LEGOSpec 把草稿模型沿四个轴分解：

  • Context：选哪些目标模型层特征、怎么融合（DFlash 的投影拼接 vs DFlare 的标量加权）；
  • Backbone：处理历史上下文、建模草稿块内依赖（MHA / GQA / SWA / GDN / MLA）；
  • Proposal：产出候选分布，可选地条件于前序 token（RNN / Markov / Selector 等）；
  • Objective：监督信号（CE / KL / TV / Mix / NLA / D-PACE / D-PAL）。

四块通过 recipe adapter 接到同一个训练器上，组件替换不用改训练循环；目标特征可在线提取或离线缓存，同一目标模型的监督可跨配方复用。控制变量实验围绕一个共享参考配置展开（DFlash context + 5 层 GQA + RNN proposal + Mix 损失，80K 样本）。

3. 三条结论

结论 1：骨干按负载选——短上下文用全注意力，长上下文用 SWA/卷积

同等参数量下，稠密 MHA/GQA 在短上下文（Regular）上占优，SWA 和 GDN 在长上下文（Long，32K–64K 输入）上反超：SWA 把 Long 从 2.450 提到 3.023，GQA 加卷积提到 2.950。机制解释很清晰：上下文变长时，全注意力的历史 key 集不断膨胀，注意力质量被历史分走，草稿块内的信息交换被稀释（2K→32K 时多数 query 头分给块内的注意力质量明显下降）；SWA 用固定窗口截断历史，块内注意力几乎不受影响。卷积则提供一条独立于注意力的块内通路——而且两者收益会互相抵消：SWA 窗口收窄时卷积的增益递减，窗口为 1 时转负，说明它们在补同一件事。

另一笔账是显存：SWA/GDN 的历史状态有界，缓存比全注意力小约 500 倍。同内存预算下，SWA 让 Qwen3.5-9B 的最大可用上下文从 18.5K 扩到 133K（7.19 倍）。

结论 2：Proposal 要在「接受」和「延迟」之间讨价还价

RNN 逐位置递归更新，接受长度最高，但每个采样步后都有额外计算，全在起草的关键路径上；Selector 把相邻候选的转移打分全部并行算，接受略低，但提议延迟低，端到端加速反而接近 RNN。结论：依赖校正的价值 = 存活 token 数 × 它拖慢验证启动的时间。理想方案是保留并行打分、同时支持全词表分布校正——这直接催生了 DFlux 的 R-Corrector。

结论 3：目标函数要「局部匹配分布 + 块级优化接受长度」

两个层面的发现：

  • 局部层面：分布匹配类损失（KL、Mix、NLA）优于只用标签的 CE；但单独的 TV 损失反而垫底——对目标概率高、草稿概率极低的 token，TV 梯度接近零，收敛慢。Mix（0.1 CE+0.9 TV0.1\,\mathrm{CE}+0.9\,\mathrm{TV}）用 CE 项在低重叠区补梯度、TV 项在收敛区对齐分布，两头都占。
  • 块级层面：后面的 token 只有在前缀全被接受时才贡献接受长度。D-PACE、D-PAL 这类前缀感知加权在 Regular 上都超过了对应的局部损失，说明接受长度应该作为聚合目标。

4. DFlux：结论拼出来的通用草稿

三条结论各取最优，拼成 DFlux：

  • SWA–GQA 混合骨干：4 层 SWA + 1 层稠密 GQA + 块内卷积——SWA 保块内注意力、卷积补局部依赖、最后一层 GQA 看全历史，只有它保留随上下文增长的缓存；
  • Residual Corrector（R-Corrector）：实测 top-16 候选覆盖了 99% 的目标–草稿分布重叠，于是只对 top-kk 候选做校正、其余词表沿用骨干 logits。校正量是 k×kk\times k 的表，所有位置并行计算；配合拒绝采样，理论上仍严格保持目标分布；
  • 层级监督：骨干输出用辅助 KL（保证候选覆盖），最终输出用 D-PAL（优化块级接受长度），两者都用全词表。
Ltrain=λaux LKL(p,qbase)+LD-PAL(p,qfinal)\mathcal{L}_{\mathrm{train}}=\lambda_{\mathrm{aux}}\,\mathcal{L}_{\mathrm{KL}}(p,q^{\mathrm{base}})+\mathcal{L}_{\text{D-PAL}}(p,q^{\mathrm{final}})

消融显示每个部件都在涨：混合骨干把 Long 提高 14.6–24.5%；R-Corrector 在 Mix 损失下 Regular 超过 RNN；层级监督再上一层。最终在 Qwen3-4B、Qwen3.6-35B-A3B、Gemma4-12B-it 三个目标模型、10 个 workload 上全部第一：

5. 训练设施本身也是贡献

框架层面还有两件实事：

  • 元数据感知调度：训练序列的长度、锚点布局、监督掩码都是已知的，可以前瞻分组、按估算成本（注意力/FFN/词表的开销模型）把样本均衡分到各 draft worker——等长样本的锚点数不同，实际计算量能差 1.79 倍，只按长度调度根本看不见；
  • 异步监督流水线：CPU 批准备、监督 I/O 与 GPU 训练重叠，目标 worker 预填充下一批。

合计：训练吞吐比 SpecForge 最高 +79%，离线监督准备最高 3.11 倍。

6. 我的看法

  • 方法论价值大于配方价值。「训练配置差异能盖过架构差异」这个观察对整个草稿模型子领域都成立——今后看到「方法 X 比 Y 好」的论文，第一反应应该是查它们的训练配置是否可比。LEGOSpec 把这件事工具化了，而且代码和权重都开源了。
  • DFlux 是目前开源里值得认真试的通用草稿。三个目标模型、10 个 workload 全胜 + 长上下文大幅领先，加上 R-Corrector 的 top-16 校正设计（99% 重叠覆盖）是个很聪明的工程折中——保留了全词表监督和理论无损，又把校正开销压到小候选集上。
  • 和同日的 Draft Calibration 正好互补。那篇管「训好之后怎么调」（草稿温度降到 0.4–0.6 白拿 10%），这篇管「怎么训」（组件化 + 层级监督）。一个有意思的交叉问题：DFlux 训出来的草稿还「不自信」吗？如果层级监督顺带修正了分布形状，温度缩放的增益空间应该会缩小——这本身就是检验训练配方的探针。
  • 长上下文是差异化卖点。SWA 混合骨干 + 紧凑缓存让 24 GiB 单卡能撑 133K 上下文的草稿，这在「长上下文 + 投机解码」这个越来越常见的场景里是实打实的能力。
