Draft Calibration：给草稿模型降降温，白捡 10% 的投机解码加速

Draft Calibration for Speculative Decoding: Accelerating LLM Serving by Matching Draft and Target Distributions
Yuxing Liu, Tong Zhang · UIUC；Wei Zuo, Walid Krichene, Li Zhang · Microsoft · arXiv:2611.33111 v1 2026-11-24

一句话：社区开源草稿模型普遍「不自信」——top-1 候选学对了，但给的概率比目标模型平。不用重训、不用改架构，只需把草稿温度从 1 降到 0.4–0.6，接受长度提升约 5–10%，在线吞吐提升近 10%，零额外成本且完全无损。更妙的是，作者用「轨迹回放」把百万次校准实验压到 GPU 分钟级，还顺带证明了：更复杂的校准方法目前反而打不过这一个超参数。

1. 问题：接受率被一个 L1 距离锁死

投机解码的加速比取决于草稿 token 的接受率，而它有闭式解——在目标分布 pp 和草稿分布 qq 下，单个草稿 token 被接受的概率是：

P(xt 被接受)=∑x∈Vmin⁡(p(x),q(x))=1−12∥p−q∥1\mathbb{P}(x_t \text{ 被接受})=\sum_{x\in\mathcal{V}}\min(p(x),q(x))=1-\tfrac{1}{2}\left\|p-q\right\|_1

所以提升加速的路只有两条：让草稿模型「选对」（top 候选与目标一致），或者让它「给对概率」（分布形状贴近目标）。已有工作几乎全在第一条路上卷——改架构、改训练目标、改特征融合。这篇论文问的是第二条：训练完之后，能不能只靠事后校准草稿分布，就把 ∥p−q∥1\|p-q\|_1 压下去？

这个视角借自经典的置信校准（Guo et al., 2017）：分类模型不仅要选对类别，预测概率还要匹配真实正确率。在投机解码里这个框架反而更干净——目标分布就是「真值」，接受率就是现成的校准评价指标。而且只要校准后的分布 qq 在起草和拒绝采样两处一致使用，投机解码的无损性质原封不动。

范围限定：全文只研究链式起草（chain drafting），动机是大规模并发服务下草稿树的验证开销不划算——引用的实验里 batch 64 时 21-token 树已经比自回归还慢。这个取舍跟他们盯的「服务吞吐」场景一致。

2. 核心观察：草稿模型集体「不自信」

作者在 9 对目标–草稿模型（GPT-OSS-120B、Gemma-4-31B、Qwen 系列 × EAGLE-3 / DFlash / DSpark）、8 个基准（数学、代码、对话）上做了系统体检，发现两件矛盾的事：

  • 候选选得挺对。top-1 候选与目标分布的重合率约 70% 以上，top-16 仍有 40%+——草稿模型「认字」的能力没问题。
  • 但概率给得太平。在 top-1 一致的那些位置上，草稿模型给 top-1 的概率一致低于目标模型，分布熵也一致偏高。也就是说，草稿分布系统性偏「平」，这就是所谓的 underconfident。

这有点反直觉——训练目标明明就是逼近目标分布。作者猜测与草稿模型容量有限有关，也可能是训练配方的问题：标准管线用的 KL 损失本身就和 ℓ1\ell_1 距离有偏。有个佐证很有意思：DeepSeek 训练的草稿模型是例外，它们的 top-1 概率差距小得多，温度缩放对它们几乎没增益（最好情况也只有 2%）——说明这个「不自信」不是必然属性，而是训练配方留下的指纹。

3. 方法：从温度缩放到 token 级校准，逐级加码

3.1 温度缩放：一个超参数就够

草稿模型和目标模型的温度本来是绑在一起用的（Td=Tt=1T_d=T_t=1）。作者把 TdT_d 拆出来当独立校准参数：

pcal=softmax ⁣(zTd)p_{\mathrm{cal}}=\mathrm{softmax}\!\left(\frac{z}{T_d}\right)

降温让分布变尖、top 候选概率升高，正好对症「不自信」。在 Td∈{0,0.2,…,1.2}T_d\in\{0,0.2,\dots,1.2\} 网格上扫一遍，结果非常一致：

  • 所有设置下接受长度对 TdT_d 近似单峰，峰值都在 [0,0.8][0,0.8]；
  • 曲线在峰值附近很平，Td∈[0.4,0.6]T_d\in[0.4,0.6] 就能拿到接近最优的增益，几乎不用精调；
  • 平均接受长度提升约 5–10%（例：Qwen3.6-35B-A3B + DFlash 从 5.275 到 5.773）；不同任务的最优温度高度一致，一个全局温度通吃。

3.2 Dirichlet 缩放：更精细，但没赢

温度缩放只有一个标量，自然会问：逐 token 的精细缩放能不能榨出更多？Dirichlet 缩放是它的推广：

pcal=softmax ⁣(Wlog⁡p+b)p_{\mathrm{cal}}=\mathrm{softmax}\!\left(W\log p+b\right)

词表太大，实际只对 top-KK 候选配 K×KK\times K 的 W(K)W^{(K)}、其余 token 共享一个标量温度。为了高效筛这类方法，作者设计了轨迹回放：保存固定参考轨迹上各位置的草稿/目标末层隐状态，回放时恢复 logits 直接算 1−12∥p−q∥11-\frac12\|p-q\|_1，不用真跑推理。百万次评估从「百万 GPU 小时」压到「GPU 分钟」，回放与在线趋势的平均相对误差只有 1.8–2.6%。

结果：对角阵穷举（8 个温度、167 万组合）比温度缩放只多不到 0.1%；全矩阵训练反而略差。结论是温度缩放已经吃掉了「跨 token 共享」的那部分分布差距。

3.3 Token 级校准头：空间存在，但抓不住

最有信息量的实验是 oracle 对照：如果每个位置都能「开天眼」选最优温度，接受长度还能再涨一截——这个空间甚至大于温度缩放本身带来的提升。而且只用 {0,1}\{0,1\} 两档温度的 oracle 就能拿到完整网格 70–76% 的增益，说明 token 级模式是存在的、且可能很简单。

但作者训练的轻量校准头（输入草稿隐状态、或再拼上前一验证块的目标隐状态，预测温度或二选一）全部失败——要么贴平全局温度缩放，要么更差。空间是真的，纯事后方法够不着，这是全文最诚实的结论。

4. 服务端收益：真金白银的吞吐

温度缩放不加任何计算，接受长度的增益直接兑现为吞吐。在线服务测试（held-out 测试集、三种子平均）：

GPT-OSS-120B / EAGLE-3643.104 → 3.436 (+10.7%)1582.6 → 1756.3 (+11.0%)

并发 128 时 DSpark 的吞吐增益（+19.5%）远超接受长度增益（+8.8%），作者归因于连续批处理的放大效应。另外推理强度（reasoning effort）越高，最优草稿温度越接近 1——因为目标分布本身也变平了。

5. 我的看法

  • 工程价值极高，成本约等于零。改一个超参数、SGLang/SpecForge 栈直接可用，10% 上下的吞吐白拿。如果你的草稿模型不是 DeepSeek 出品，这个实验值得今天就做。
  • 轨迹回放是方法论上的亮点。把「校准方法筛选」从在线评测的暴力循环里解放出来，这个框架对任何做草稿分布研究的人都直接可复用。
  • 诚实的负结果比正结果更有信息量。Dirichlet 缩放和校准头双双失败，说明「不自信」是全局性的、跨 token 共享的偏移，一个标量就能修；而剩下的 token 级空间，纯事后方法够不着，得进到训练侧去解决——这正好和训练时的接受率优化（如 D-PAL、NLA 那条线）接上了。
  • DeepSeek 例外是最值得追的线索。同样是草稿模型，为什么它们训练出来就「自信」？如果训练配方（损失函数、数据配比）能解释，那这篇论文的终极贡献其实是给草稿模型训练立了一面镜子。
