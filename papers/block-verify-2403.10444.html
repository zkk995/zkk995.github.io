Block Verification：把投机解码的“逐 token 验收”改成“整块联合验收”，白捡 5–8% 加速

Block Verification Accelerates Speculative Decoding
Ziteng Sun, Uri Mendlovic, Yaniv Leviathan, Asaf Aharoni, Ahmad Beirami, Jae Hun Ro, Ananda Theertha Suresh · Google Research · arXiv:2403.10444 v2（2024-07-25）

一句话：投机解码沿用三年的“逐 token 验收”其实不是最优——这篇论文证明：把整块草稿联合起来一起验收，在完全保持输出分布不变（无损）的前提下，每轮期望产出的 token 数严格不少于任何其他合法验收算法；实测在 8 个数据集上墙钟时间稳定再快 5–8%，代码几乎零改动，可以直接当默认验收算法用。

1 · 背景：投机解码与“逐 token 验收”

投机解码的流程：小模型（drafter）快速起草 γ 个 token，大模型（target）一次并行前向把这 γ+1 个前缀全部打分，然后按拒绝采样规则决定接受哪些，被拒处从残差分布补采一个 token。Leviathan 等人 2022 年定下的标准验收是逐 token 独立做拒绝采样：

accept Xᵢ ~ 以概率 min(1, M_b(Xᵢ|c,X^{i-1}) / M_s(Xᵢ|c,X^{i-1}))

这个“token-by-token”流程是后续所有投机解码工作（EAGLE、Medusa、各类 DFlash 草稿模型）沿用的标准。本文的问题是：这个环节本身，还有没有免费的优化空间？

2 · 反直觉的发现：逐 token 验收丢了“联合信息”

作者用一个双 token 小例子揭示问题。设词表只有 a、b 两个 token，两个模型都与上下文无关：M_b(a)=1/3、M_b(b)=2/3，M_s(a)=2/3、M_s(b)=1/3。逐 token 验收下，b 必收、a 以 1/2 概率收，γ=2 时每轮期望接受 10/9 个 token。

但如果我们能看整块的联合分布：M_b 对 (a,b)、(b,a)、(b,b) 的联合概率都不小于 M_s，这三种整块可以无条件全收（逐 token 验收做不到——比如 (a,b) 里的 a 会被它单独卡掉）；只有 (a,a) 需要以 1/4 概率拒绝。联合验收后期望接受数变成 12/9，比 10/9 多出 11%——同样的草稿、同样的大模型打分，白白多接受了一部分。

关键点：只需要“沿草稿路径”的条件分布

完整联合分布通常算不动，但作者证明：验收决策只需要投机解码本来就拿得到的东西——大模型并行前向沿草稿路径返回的各步条件分布 M_b(·|c,X^i)。算法只需在逐 token 结果之上，额外沿草稿路径把“该步被拒时的残差分布”乘进联合 acceptance 权重，整块联合判定即可。这就是 Block Verification：不多算一次前向、不改采样架构。

3 · 理论保证：分布不变 + 全场最优

  • 定理 1（无损）：Block Verification 产出的序列分布与直接从大模型采样完全相同——和标准投机解码一样的强保证，不是近似。
  • 定理 2（最优）：在所有“保持输出分布”的合法验收算法中，Block Verification 的每轮期望产出 token 数全局最优，因此永远不差于逐 token 验收。
  • 边界说明：存在“接受决策依赖上一轮结果”的更强算法（附录 C 的 greedy 变体），单轮期望更高，但会拖慢后续轮次、实测反而更差——Block Verification 是“每轮最优 + 全局实用”的甜点位。

4 · 实验：8 个数据集，一致 5–8% 墙钟加速

实验用 PALM-2-S 做目标模型、PALM-2-XXS 做草稿模型，γ=8，覆盖语言建模、对话、问答、常识推理、数学（GSM8K）、摘要、翻译共 8 个数据集，每数据集 1000 条 prompt、3 个种子：

指标（相对 TokenV 的提升）范围平均
Block efficiency（每轮期望 token 数）+7.0% ~ +10.1%+8.30%
Wall clock time（真实加速）+5.4% ~ +8.1%+6.49%

规律：γ 越大提升越大（γ=4、6 时提升相应变小）；草稿模型越弱、与目标模型差异越大，联合验收捡回来的 token 越多。改进只发生在验收阶段，与改进草稿阶段的工作（更好的 drafter、树形草稿等）正交可叠加。

5 · 为什么这篇值得记住

  • “意外地简单”的典型样本：一个 2022 年定下的行业标准环节，被证明有严格更优的替代，而且替代品几乎不增加代码复杂度——工程上“没有理由不用”。
  • 对推理加速管线是纯增量：如果你在用投机解码（包括 DFlash 这类草稿模型方案），验收算法从逐 token 换成整块联合，是无损保证下的免费加速；推理框架侧（vLLM/SGLang 等）合入后默认受益。
  • 方法论启示：优化“流水线某一段”时，先证明当前做法在合法算法空间里的位置——它常常不在最优处，而证明最优性本身（Thm 2）比凑 1% 的经验收益更有价值。
