Draft-OPD 论文解读：让投机解码的小模型在“自己的错误”上继续进化

上海交通大学 · 上海人工智能实验室 · 清华大学 · 香港中文大学 等 ｜ CC BY 4.0 ｜ arXiv:2605.29343

这篇论文正面回答了训练类投机解码的痛点：草稿模型（EAGLE-3、DFlash 这类）用监督微调训练到一定程度就停滞了，接受长度上不去。作者把病根定位成“训练看的状态和推理走的状态不是一批”，然后借用在线蒸馏（OPD）的思路，设计了一套让草稿模型真正“在岗训练”的方案。

一句话核心：用目标模型护航采样保住质量，把验证时暴露的“草稿犯错位置”记录下来并重放，让目标模型在这些草稿亲历的状态上打分——接受的部分用正向 KL 巩固、拒绝的部分用反向 KL 纠错，最终让思考型模型拿到 5 倍以上的无损加速，比 EAGLE-3 快 23%、比 DFlash 快 13%。

一、背景：草稿模型的“SFT 天花板”

投机解码的原理很直白：小草稿模型一口气猜 K 个 token，大目标模型并行验证，接受的留下、拒绝的重来，输出分布与大模型完全一致（无损）。加速比的关键指标是接受长度τ\tau——每轮验证平均能白拿几个 token，草稿模型和大模型越合拍，τ\tau 越高、加速越猛。

主流做法（EAGLE-3、DFlash）都是拿目标模型生成的轨迹做监督微调（SFT）。但作者给出了一条关键训练曲线：SFT 热身之后，继续训接受长度不再涨，在平台期反复横跳；更蹊跷的是，拿 OPD 同源的更多数据继续 SFT 甚至会把接受长度训低。

病根：训练与推理的状态错配。SFT 里草稿模型见到的每个前缀都是目标模型生成的（目标分布的状态）；可推理时接受长度恰恰由“草稿模型自己提议的块”决定——它在自己引入的偏差状态上表现如何，SFT 从来没教过。这是强化学习里经典的 exposure bias 在投机解码里的变体。

二、为什么“直接上在线蒸馏”行不通

在线蒸馏（OPD）的药方是：让学生在自己走出的状态上接受老师监督：

LOPD=Est[DKL(pθt ∥ qϕt)]\mathcal{L}_{\mathrm{OPD}}=\mathbb{E}_{s_t}\left[D_{\mathrm{KL}}(p_\theta^t\,\|\,q_\phi^t)\right]

但套到草稿模型上立刻卡壳，两条路都堵死：

✗ 草稿模型自己采样

EAGLE/DFlash 这类草稿头是为“跟在目标模型后面猜几个 token”设计的，独立自回归续写会迅速复读、退化，产出的状态本身就是垃圾，监督信号不可靠。

✗ 目标模型护航采样

让目标模型带着草稿模型 rollout 能得到高质量序列，但投机验证是无损的——被接受的续写完全服从目标分布，草稿犯的错（被拒绝的提议）被直接扔掉，而这些错误恰恰是最有价值的训练信号。转了一圈又回到离线 SFT。

三、Draft-OPD：护航采样 + 错位重放

Draft-OPD 的巧思在于把两条死路接成一条活路：用目标模型护航保证 rollout 稳定，但把草稿“当时 propose 了什么”完整记账，事后重放。三个部件环环相扣：

① 护航采样 + 记锚点
正常跑投机解码收集目标质量的序列，同时把每轮草稿块的起始位置记为“锚点”。锚点就是草稿模型推理时真正“行动过”的状态快照。
② 从锚点重放
从每个锚点重放上下文 cm=(x, y≤am)c_m=(x,\,y_{\le a_m}) 中的草稿块 dm=(dm,1,…,dm,K)∼qϕ(⋅∣x, y≤am)d_m=(d_{m,1},\ldots,d_{m,K})\sim q_\phi(\cdot\mid x,\,y_{\le a_m})，让学生（草稿）和老师（目标）在同一批草稿提议的前缀上算对数概率，包括被验证拒绝的位置。
③ 分而治之的蒸馏目标
验证结果天然把草稿 token 分成“被接受的”和“被拒绝的”，两类用不同方向的 KL 分别处理。

重放时学生与老师的打分：

log⁡qm,k(dm,k)=log⁡qϕ(dm,k∣cm, dm,<k)\log q_{m,k}(d_{m,k})=\log q_\phi(d_{m,k}\mid c_m,\,d_{m,<k})
log⁡pm,k(dm,k)=log⁡pθ(dm,k∣cm, dm,<k)\log p_{m,k}(d_{m,k})=\log p_\theta(d_{m,k}\mid c_m,\,d_{m,<k})

验证结果把草稿 token 分为接受集与拒绝集：

Iacc={(m,k):1≤k≤rm},Irej={(m,k):rm<k≤K}\mathcal{I}_{\mathrm{acc}}=\{(m,k):1\le k\le r_m\},\quad\mathcal{I}_{\mathrm{rej}}=\{(m,k):r_m<k\le K\}

接受与拒绝，两种 KL 方向

被接受的 token：草稿已经和大模型对上号了，用正向 KL DKL(p ∥ q)D_{\mathrm{KL}}(p\,\|\,q) 让草稿的分布去覆盖目标分布，巩固既有的一致性：

Lacc=1∣Iacc∣∑(m,k)∈IaccDKL ⁣(pm,k ∥ qm,k)\mathcal{L}_{\mathrm{acc}}=\frac{1}{|\mathcal{I}_{\mathrm{acc}}|}\sum_{(m,k)\in\mathcal{I}_{\mathrm{acc}}}D_{\mathrm{KL}}\!\left(p_{m,k}\,\|\,q_{m,k}\right)

被拒绝的 token：草稿自信地猜错了。用反向 KL DKL(q ∥ p)D_{\mathrm{KL}}(q\,\|\,p) 惩罚草稿自己的高概率模式——正向 KL 在这种状态下会让草稿把概率摊到老师所有可能选项上（均值化），反向 KL 则逼着它在老师不同意的模式上直接降权。另外，一个块开头的错误会连累后面整段（前面被拒，后面写对也没用），所以越靠前的拒绝越重要，用指数衰减加权：

Lrej=1Z∑(m,k)∈Irejwk DKL ⁣(qm,k ∥ pm,k)\mathcal{L}_{\mathrm{rej}}=\frac{1}{Z}\sum_{(m,k)\in\mathcal{I}_{\mathrm{rej}}}w_k\,D_{\mathrm{KL}}\!\left(q_{m,k}\,\|\,p_{m,k}\right)  wk=γk−1w_k=\gamma^{k-1}

最终目标就是两者的加权平均（实验里两个权重各取 1）：

LDraft-OPD=λaccLacc+λrejLrejλacc+λrej\mathcal{L}_{\mathrm{Draft\text{-}OPD}}=\frac{\lambda_{\mathrm{acc}}\mathcal{L}_{\mathrm{acc}}+\lambda_{\mathrm{rej}}\mathcal{L}_{\mathrm{rej}}}{\lambda_{\mathrm{acc}}+\lambda_{\mathrm{rej}}}

工程上很省：重放所需的目标模型隐状态在采样时已经算过，直接复用，不用重跑大模型。

四、实验：思考型模型首次突破 5 倍无损加速

实验对象是 Qwen3-4B/8B（开/关思考模式 × 温度 0/0.6），任务覆盖数学（GSM8K、MATH-500、AIME25）、代码（MBPP、HumanEval、SWE-Lite）和对话（MT-Bench），草稿头沿用 DFlash 式并行结构，训练算力对齐对比。

EAGLE-3（Q3-4B）4.41×4.15×3.30×4.29×3.87×5.33
DFlash（Q3-4B）4.51×4.88×4.69×4.39×4.33×5.51
Draft-OPD（Q3-4B）5.31×5.55×5.28×4.85×4.86×5.96
EAGLE-3（Q3-8B）4.58×4.45×4.01×4.55×4.06×5.64
DFlash（Q3-8B）4.67×5.01×4.77×4.50×4.34×5.19
Draft-OPD（Q3-8B）5.36×5.80×5.51×4.86×4.89×5.73

关思考模式更快：Q3-8B 上 Draft-OPD 平均 6.49×（MATH-500 到 7.64×）。汇总口径：思考型模型平均 5×以上无损加速，比 EAGLE-3 高 23%、比 DFlash 高 13%；SGLang 部署实测同样拿到增益。

消融：增益确实来自“在岗训练”

  • 不是数据多：拿同样的 OPD 提示词池让目标模型生成回复继续 SFT，效果明显不如 Draft-OPD——关键是在草稿亲历的状态上蒸目标的分布，不是多见几个 prompt。
  • KL 方向要分家：全正向、全反向都更差，全反向最差，混合方案最优。
  • 指数衰减有用：去掉后 MATH-500 加速从 5.55× 掉到 5.13×。
  • 朴素护航采样不行：等价于 KL 版 SFT，平均加速 4.63× → 4.29×（-7.3%），证明“保留草稿引发的错误”这一步不可省。

五、有意思的观察与局限

思考模式的“可草稿性鸿沟”：同样是数学和代码任务，思考模式下的加速明显低于非思考模式。附录 C 给了证据：思考型回复的逐 token 负对数似然（NLL）系统性更高——模型在长推理链里下一步选择更发散，草稿模型要拟合的目标分布更“平”，自然更难猜中。这说明推理内容的加速上限部分由目标模型自身的不确定性决定，是个值得单独攻的问题。

局限：训练时 rollout 截断在 4096 token（评估用 8192），超长生成后段的状态没覆盖到；实验只在 Qwen3 + DFlash 式架构上验证，换家族换框架的迁移性待考；只针对无损投机解码，近似/有损验证是开放方向。

六、点评：为什么值得读

  • 问题定位精准：把“SFT 天花板”归因到状态错配，并用训练曲线 + 消融闭环验证，逻辑链完整。
  • 方法像 RL 但不是 RL：锚点重放 ≈ 在验证轨迹上做“带事后反思的行为克隆”，接受/拒绝分区 + 双向 KL 是把验证信号（天然奖励）编译进了蒸馏目标，不需要奖励模型、不需要策略梯度。
  • 对从业者实用：框架搭在 SpecForge、verl、SGLang 这些开源设施上，“在验证期错误上做后训练”的思路可以直接迁移到自己的草稿模型流程。
  • 与 RLSVR 互补：那篇在 RLVR 侧给开放任务造可验证奖励，这篇在加速侧让草稿模型吃验证错误——一个解决“练什么”，一个解决“怎么跑得快”。
